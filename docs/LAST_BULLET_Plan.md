## 2. 게임 사양

### 2.1 핵심 루프

```
미술관(아지트)
  → 스테이지 선택·입장 (체력 최대로 시작)
  → 연사 사격 · 재장전 · 적 처치 → 재료는 '전투 가방'에 임시 보관
  → 모든 적 처치(클리어) → 재료를 창고로 정산   /   사망 → 전투 가방 전부 삭제
  → 종이 합성 → 그림 제작 → 액자 전시
  → 서로 다른 그림 9장이 액자에 걸리면 엔딩
```

### 2.4 연사 총 전투 (2026-11-04 사용자 결정: 데스티니식으로 변경)

1. 총은 연사 소총(AK47)이다. 좌클릭을 누르고 있으면 초당 약 9발 나간다. 탄창은 30발이고 **탄은 무한**이다.
2. 탄창을 다 쓰면 자동으로, 또는 R키로 재장전한다 (1.6초). 재장전 중에는 쏠 수 없다.
3. 판정은 Raycast다. 카메라 중심에서 쏜 선으로 조준점을 구하고, 총구에서 그 점으로 다시 쏘아 맞은 곳을 정한다.
4. 한 발의 피해는 10이다. **머리에 맞으면 크리티컬로 2배**다. (기본값. `AutoGun`의 damage·headshotMultiplier, 적 프리팹 `EnemyHealth`에서 바꾼다)
5. 적은 체력(HP)이 있고 0이 되면 처치된다. 처치 보상은 1회만 지급한다. 머리(크리티컬)로 처치하면 물감 1.5배.
6. 맞아도 적은 멈칫하지 않는다 (연사에 계속 멈추지 않게. AI의 `hitStunTime` 0).
7. 우클릭 조준(ADS)을 하면 시야각이 줄고 1인칭 총이 화면 가운데로 와 가늠쇠가 조준점에 맞는다. 조준 중에는 반동이 줄어든다.

**구현 기준**
- 총: `AutoGun` (연사·재장전·피해). 화면: 탄약 표시 `AmmoDisplay`(왼쪽 아래: 총 아이콘 + 큰 숫자 + ∞), 힛마커 `HitMarker`, 데미지 숫자 `DamageNumbers`, 적 머리 위 체력바 `EnemyHealthBars`, 조준점 퍼짐 `ReticleSpread`.
- 크리티컬: 적 프리팹에 머리용 Sphere Collider를 자식으로 두고 `Hitbox`로 머리/몸을 구분한다. `Hitbox.TakeHit(피해, 머리 배수, 위치)`가 `EnemyHealth.ApplyDamage`를 부른다.
- 효과: 총구 불꽃·탄피 `GunEffects`, 맞은 소리 `HitSounds`(몸 틱 / 크리티컬 딩 / 처치 퍽), 처치 연출 `EnemyDeathEffect`(쓰러진 뒤 물감 방울로 터짐).
- 카메라 반동(`ThirdPersonCamera`)과 1인칭 총 반동(`FirstPersonGun`)은 쏠 때마다 쌓이고 한계가 있다.

| 빨강 | 주황 | 노랑 | 초록 | 파랑 | 보라 | 핑크 | 하양 | 검정 |

- 색상별 최대 보유량은 500이다. 500을 넘는 획득분은 버리고 "가득 참" 알림을 표시한다.
- 색은 9색 중 균등한 확률로 랜덤하게 정해진다. 원하는 색만 골라 얻는 수단은 없다.
- 잔량이 0인 색으로는 그릴 수 없다.
- 지우개는 물감을 쓰지 않는다. 지워도 이미 쓴 물감은 돌려주지 않는다.
- 그림을 취소하거나 중단해도 쓴 물감은 돌려주지 않는다.
- **소비 공식:** `소비량 = 선 길이(px) × 펜 굵기(px) × 0.01`
  - 선 길이는 마우스 이벤트 횟수가 아니라 이전 점과 현재 점 사이 거리로 계산한다.
  - 소수 누적값은 내부에 보관하고, 인벤토리는 정수 단위로 차감한다.
  - 그림 1장 분량(약 250)으로 256×256 캔버스의 약 40%를 칠할 수 있다.

**엔딩까지 필요한 양 (참고)**
- 종이 9장 = 종이조각 45개 = 적 약 45마리 = 숲 약 6~7판
- 예상 총 플레이 시간: 약 1.5~2시간

### 2.8 그림판

- 미술관의 **그림 작업대**에서 E키를 누르면 같은 `Hideout` 씬 위에 2D UI로 열린다. 별도 씬으로 이동하지 않는다.
- 구성: 펜(굵기 2 / 5 / 10 / 20px), 색상 9종, 지우개, 물감 잔량 표시, 완성 버튼, 취소 버튼.
- 캔버스는 256×256px (기본값)이다. **정사각형으로 고정한다** (2026-10-30 변경). 액자도 모두 정사각형이다.
- 그림판을 열거나 그리기 시작할 때는 종이를 쓰지 않는다.
- **완성 버튼을 누르면 종이 1장을 소비하고** PNG로 저장한 뒤, 고유 ID로 작품 목록에 등록한다. 종이가 없으면 완성할 수 없다.
- 내용과 관계없이 완성할 수 있다. 빈 캔버스도 된다.
- PNG 저장에 성공한 뒤에만 종이를 차감한다.
- 취소하면 미완성 그림을 삭제한다. 쓴 물감은 돌려주지 않고 종이는 쓰지 않는다. 취소 전에 확인창을 띄운다.
- 강제 종료나 크래시는 취소와 같이 처리한다. 대비를 위해 그리는 동안 물감 잔량을 5초마다 자동 저장한다.
- 작품 저장 개수에는 제한이 없고, 목록은 스크롤로 보여 준다. 작품 삭제 기능은 넣지 않는다.

### 2.9 미술관과 전시

- 미술관 구성: 그림 작업대, 종이 합성대, 액자 9개, 스테이지 선택 장치(문 또는 지도), 인벤토리 UI.
- 액자 9개는 처음부터 모두 있다.
- 액자 앞에서 E키 → 작품 목록 → 그림 선택 → 액자 머티리얼의 텍스처를 교체하고, 전시 정보를 저장한다.
- 같은 그림을 여러 액자에 걸 수 있다. 전시해도 그림은 없어지지 않고 언제든 교체할 수 있다.
- 액자 UI에 "서로 다른 작품 N / 9" 진행도를 표시한다.

### 2.10 엔딩

- **조건:** 9개 액자에 **서로 다른 그림 ID 9개**가 걸린 순간. 판정은 그림 ID로 한다. 내용이 같아도 따로 완성한 그림은 서로 다른 작품이다.
- 조건을 충족하면 "이 9점으로 재개관할까요? 이후에는 그림을 바꿀 수 없습니다" 확인창을 띄운다.
- **연출:** 카메라가 액자를 따라 이동하며 걸린 9장을 먼저 보여 주고, 이어서 전시되지 않은 나머지 완성작을 만든 순서대로 각 2초씩 보여 준다. 엔딩 독백 후 "재개관" 문구로 끝난다.
- 엔딩이 끝나면 타이틀로 돌아간다. **엔딩을 본 세이브는 더 이상 플레이할 수 없다.**
- 엔딩 후 타이틀에 **'갤러리 보기'**가 생긴다. 완성된 미술관을 걸어 다니며 감상만 할 수 있고, 전투·그림판·액자 교체는 할 수 없다.
- '새 게임'을 시작할 때 기존 세이브를 덮어쓸지 확인창을 띄운다. PNG 파일은 지우지 않는다.

### 2.11 세계관과 스토리

- **배경:** 폐관한 작은 미술관
- **주인공:** 미술관을 물려받은 젊은 견습 관장. 앞치마와 베레모 차림이고, 밝지만 어설프다.
- **적 (2026-11-11 사용자 결정으로 "회색 조각상" 설정을 없애고 바꿈):** 거울 너머에서 숨겨진 색을 노리는 그림자들. 처치하면 삼킨 색이 물감으로 터져 나오고, 종이조각이 떨어진다. 맵마다 가장 큰 그림자(보스)가 색을 가장 많이 삼키고 있다.
  - 이야기의 큰 줄기: 할아버지가 돌아가신 뒤 부모님이 낡은 열쇠를 건네며 미술관을 알려 줬다. 오래 쓰이지 않은 미술관은 색을 지키려고 거울 너머에 색을 숨겨 두었고, 나는 그 색을 되찾아 그림 아홉 장으로 액자를 채운다. 자세한 내용은 `docs/claude/STORY_PLAN.md`.
  - (옛 설정, 쓰지 않음) 돌진형은 흉상, 원거리형은 소형 조각, 머리를 크게, 헤드샷에 금이 가며 색이 샘.
- **총:** 창고에 남아 있던 낡은 신호총과 탄환 한 발.
- **전달 방식:** 시작 독백과 엔딩 독백만 넣는다. 각 3~5줄 자막이다.

시작 독백·엔딩 독백 (2026-11-11 확정판으로 대체): 시작 이야기 4쪽은 `Assets/UI/0_OpeningPages.txt`, 결말 8쪽은 `Assets/UI/0_EndingPages.txt`, 할아버지 일기장 4쪽은 `Assets/UI/Diary_01~04.png`에 있다 (모두 직접 쪽을 넘기는 창). 옛 초안(회색 조각상, 낡은 총 한 자루)은 쓰지 않는다.

### 2.12 아트와 에셋

- **로우폴리**, 밝고 캐주얼한 분위기다. 회색 조각상과 원색 물감의 대비가 아트 방향의 중심이다.
- 공포, 바다, 우주, 뜨개질·실 콘셉트는 사용하지 않는다.
- **기성 에셋과 직접 만든 모델을 섞어 쓴다.**
  - 직접 제작 우선순위 (기본값): ① 주인공 ② 조각상 3종 ③ 총·탄환 ④ 액자·작업대
  - 에셋 사용 (기본값): 숲 지형, 나무, 바위, 미술관 기본 건물
  - 스타일 통일 규칙: 단색 머티리얼 또는 팔레트 텍스처 하나, 비슷한 폴리곤 밀도, 같은 조명과 후처리
  - 에셋 출처와 라이선스는 `Assets/Credits.txt`에 기록한다.
- 기능을 구현하는 동안에는 Capsule, Cube 같은 임시 도형을 쓰고, M3에서 모델로 교체한다.

## 3. 기술 설계

### 3.1 스택

| 분야 | 사용 |
|---|---|
| 렌더링 | Unity 6 URP |
| 입력 | New Input System |
| 이동 | CharacterController |
| 카메라 | Cinemachine 3인칭 |
| UI | uGUI + TextMeshPro |
| 사격 | Raycast + `Hitbox` |
| 적 AI | 상태 기반 + NavMesh |
| 그림판 | Texture2D + RawImage, `EncodeToPNG()` |
| 데이터 | JSON (JsonUtility), `Application.persistentDataPath` |
| 씬 간 유지 | `DontDestroyOnLoad` 관리자 |

### 3.2 씬

| 씬 | 역할 |
|---|---|
| `MainMenu` | 새 게임, 이어하기(엔딩 전), 갤러리 보기(엔딩 후), 옵션, 나가기 |
| `Hideout` | 미술관: 작업대, 합성대, 액자 9개, 스테이지 선택. 갤러리 보기 모드 겸용 |
| `Stage_Training` | 훈련장 |
| `Stage_Forest` | 숲 |
| `Ending` | 회고 연출 (`Hideout` 안의 연출로 대체해도 된다) |

흐름: `MainMenu → Hideout ↔ Stage_*` → `Ending` → `MainMenu` → (갤러리 보기) `Hideout`

### 3.3 폴더 구조

```text
Assets/
├── Scenes/            MainMenu, Hideout, Stage_Training, Stage_Forest
├── Scripts/
│   ├── Core/          GameManager, SceneLoader, SaveManager
│   ├── Player/        PlayerMovement, ThirdPersonCamera, PlayerHealth, PlayerInteraction
│   ├── Combat/        AutoGun, Hitbox, GunEffects, RifleReloadTimeline
│   ├── Enemy/         EnemyAI, EnemyHealth, EnemyDrop
│   ├── Stage/         StageManager, RunBag
│   ├── Inventory/     InventoryManager, PaperCrafting
│   ├── Drawing/       DrawingDeskInteraction, DrawingCanvas, PaintManager, DrawingSaveManager
│   ├── Gallery/       PictureFrame, GalleryManager, EndingSequence
│   └── UI/            BattleUI, InventoryUI, DrawingUI
├── Prefabs/  Materials/  Models/  Textures/  UI/  Audio/  Animations/
└── Credits.txt
```

### 3.4 시스템 연결

- `AutoGun` → Raycast → `Hitbox`(머리/몸) → `EnemyHealth`(HP, 크리티컬) → 화면 표시(`HitMarker`·`DamageNumbers`·`EnemyHealthBars`)와 `HitSounds`
- `EnemyHealth` 사망 → `EnemyDrop` → `RunBag`(전투 가방)
- `StageManager` 클리어 → `RunBag.Settle()` → `InventoryManager` (상한 500 적용)
- `PlayerHealth` 사망 → `RunBag.Clear()` → `Hideout` 복귀
- `AutoGun` 발사 → `GunEffects`(불꽃·탄피), 카메라·1인칭 총 반동, `AmmoDisplay`(탄약)
- `EnemyHealth` 사망 → `EnemyDeathEffect`(쓰러짐·터짐)
- `DrawingCanvas` → `PaintManager` → `InventoryManager` 물감 차감
- 완성 → `DrawingSaveManager` PNG 저장 → 성공 시 종이 차감 → 작품 목록 등록
- `PictureFrame` → `GalleryManager` (서로 다른 ID 9개 감지) → 확인창 → `EndingSequence`

### 3.5 저장 데이터

```text
persistentDataPath/SavedData/
├── save.json        # 인벤토리, 물감, 해금 스테이지, 엔딩 여부
├── paintings.json   # 작품 ID, 파일명, 생성일
├── gallery.json     # 액자 9칸의 그림 ID
└── Paintings/       # painting_<ID>.png
```

```json
{
  "paperScraps": 12,
  "drawingPaper": 2,
  "paints": {
    "red": 350, "orange": 210, "yellow": 500, "green": 120, "blue": 430,
    "purple": 75, "pink": 260, "white": 190, "black": 150
  },
  "unlockedStages": ["Training", "Forest"],
  "endingSeen": false
}
```

- 물감은 메모리에서 바로 차감한다. 디스크에는 주요 상태가 바뀔 때와 그림판을 쓰는 동안 5초마다 저장한다. 마우스 이벤트마다 저장하지 않는다.
